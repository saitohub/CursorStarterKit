# 第2項 — カバー（なぜこのフォルダー構成なのか、基礎用語と設計の意図と企画について）

第1項でゴールと流れを掴んだうえで、**なぜこの Vault のフォルダー構成なのか**、**用語**、**設計の意図**、**企画の狙い**を自分の言葉で残す入口。

---

## なぜこのフォルダー構成なのか

- 同じ **Vault** を Cursor（作る）と Obsidian（読む）で見る。**01〜07** で AI が文脈を推測しやすくする
- 詳細 → [[第2講 - 基礎用語とフォルダ設計]]

## 基礎用語（聞いた定義をそのまま短く）

| 用語 | メモ |
|------|------|
| AIモデル | 賢いがチャット単位の記憶。会社・得意が違う |
| LLM / コンテキスト | 長いと精度↓・消費↑ |
| API | 使った分課金の裏口。Cursor はこちら寄り |
| Markdown | `.md` 原本。AI が読みやすい |
| Vault | Obsidian の倉庫全体。Cursor と同じフォルダ |
| クレジット | Cursor の残量。テキスト量≒コスト |
| 企画（講義） | ファイル名・場所のルールで AI が判別 |

→ 3本目分は [[第3講 - AIモデルとAPI（ジャーナル生データ要約）]]

## 設計の意図（作り手の意図と、自分への当てはめ）

- 個人技ではなく **精度とコストを構造で担保**。ファイルが増えるほど AI が賢く、手直しとクレジットが減りやすい
- 詳細 → [[第2講 - 基礎用語とフォルダ設計]] の「企画あり vs なし」

## 企画について（この講座／プロダクトが解きたい課題）

- 講義上の「企画」＝ **命名・フォルダ規則**（要確認: Markdown そのもの、というメモもジャーナルにあり）
- 課題: 企画なしだと AI が毎回丸読み → 課金地獄・精度ブレ

## 受講の学び（一言）

- **倉庫を2つの窓口で使い分け、名前で AI に文脈を渡す** と、マニュアルが「だからこう」とつながる
