## 基礎用語（モデル・API・形式）

### AIモデル

- ChatGPT / Claude / Gemini などは総称して **AIモデル**
- ざっくり：**頭はいいが、記憶はないアシスタント**（正確には **チャットごとの文脈**）
- 翌日には忘れたように感じる → チャットが切れると文脈も切れる、という理解
- 会社ごとに得意分野・文体・料金が違う
- 同じモデルでも **中規模／大規模** など処理能力の段階があり、複雑な作業ほど消費が増える

### LLM とコンテキスト

- **LLM**（大規模言語モデル）：上記チャット系の基盤
- チャットが長くなると **精度が落ちやすい**（コンテキストが複雑化・消費増）
- 普段は中規模で回し、難しいときだけ大規模、という運用イメージ

### API（裏口）

- **表（サブスク）**: 月額（例：20ドル級）で使い放題に近いが、リセットされ、記憶なし、できることが制限されがち
- **裏（API）**: 使った分だけ課金。自分のツールから AI を直接呼べる
- **Cursor が裏でやっているのは API 側**、という理解

### Markdown（`.md`）

- 世界で最もシンプルなテキストの書き方ルール（`#` 見出し、`**` 太字、箇条書きなど）
- **中身は純テキスト** → AI が読みやすい
- Word / PDF / Notion 独自形式は AI にとって余計なことが多い
- **ルール**（口調・ターゲットなど）も Markdown で書ける（`.cursor/rules` など）
- **20年以上仕様がほぼ変わらない** → ツールが消えてもフォルダごと持ち運べる（Type-C 的な共通規格）
- PDF・スライドは **原本（Markdown）から変換して出す**

**注意**: 原本は Markdown で持つ。**バックアップ**はローカル・外付け・GitHub・iCloud など複線で。

### Vault（ボルト）

- Obsidian で **ノート倉庫全体** を指す用語
- **Cursor と Obsidian は同じ Vault（同じフォルダ）を開く** → 連携できる理由
- 比喩：**同じ倉庫を、AI用の窓口（Cursor）と人間用の窓口（Obsidian）から見ている**

### クレジット・トークン

- Cursor では AI 処理に **クレジット**（残り HP のようなもの）が減る
- 指示のたびに消費。プランで月上限あり
- **画像・PDF** はテキストより重い（画像処理扱いになりやすい）→ **Cursor の Vault には置かない**（参照・処理でクレジットが跳ねやすい）
- 細部は **トークン** 単位だが、まずは **テキスト量 ≒ コスト** で覚える

**自分メモ**: 今まで PDF・音声・動画を PC に溜め、AI に読ませると、勝手に参照されて処理コストがかかる、と理解した。これからは、動画・音声で学んだことを **音声入力で MD（01 か 04）に残す** 習慣にする。

## Cursor と Obsidian の役割分担

| | Cursor | Obsidian |
|---|--------|----------|
| 役割 | AIと**作る**・生成・編集 | **読む**・確認・リンク・グラフ |
| 向くこと | ルール・スキル・コマンドが動く、`.cursor` が見える | 読みやすい表示、PDF書き出し |
| 注意 | **同時編集**すると上書きの可能性 → **作業は Cursor で完了 → Obsidian で確認** |

## フォルダ構成（01〜07）

| 番号 | フォルダ | 役割 |
|------|----------|------|
| 01 | Notes | 一時置き場・下書き・未分類メモ |
| 02 | Configs | テンプレート・設定（日常はあまり触らない） |
| 03 | Knowledge | **知的資産**（最重要） |
| 04 | Journals | 日々のジャーナル（生データ） |
| 05 | Outputs | 完成コンテンツ（note 等） |
| 06 | Reflections | 週次・月次の振り返り |
| 07 | Swipe | 他人の参考事例（構造の参考のみ） |

**番号の理由**

- AI が **番号だけで文脈** を推測しやすい（01＝素材、05＝完成品 など）
- ルールがバラバラだと毎回「これ何ですか？」となり、**精度↓・手間↑・クレジット↑**

**増やしてよいか**

- 初期構成は **ベース**。運用でサブフォルダ追加は OK（例：05 の下にメルマガ）
- ただしフォルダを増やしすぎると、AI が読む量が増え **課金・判断コスト** が上がる（部屋を増やすと引っ越しが大変、の比喩）

### 03_Knowledge の4分割

| 種類 | 中身 |
|------|------|
| Story | 自分（または引用した）体験・エピソード |
| Logic | 理論・ノウハウ・例えの束ね |
| Evidence | 外部の根拠・データ・学術など |
| Claim | 自分が断言できる主張 |

**4つ揃うと**、主張だけより感情と行動につながりやすい、という講義の整理。  
ジャーナルからの自分メモ：Claim → Evidence → Story → Logic（例え）の流れで関連づけている、という実感あり。

振り分け例：ジャーナルで「資産化できそう」と思ったら、Cursor に **Knowledge へ振り分けて** と頼む。音声メモは 01 か 04 に入る（Obsidian で無題ファイルを開いたときのテンプレ先）。あとで AI に振り分ければよい。

## `.cursor` フォルダ（隠しフォルダ＝会社の管理部門）

- 名前が **`.` で始まる** → 多くの環境では隠しフォルダ（Obsidian では見えないことも、Cursor では見える）。PC のシステム領域に近いが、**AI 運用の管理者は自分**。難しい整理は AI に頼める。
- 中身の比喩（講義）:
  - **会社全体** = Cursor
  - **社長** = あなた、**社員** = AI
  - **`.cursor`** = 管理部門の書類

| 中身 | 比喩 |
|------|------|
| rules | 社則・トーン・ターゲット |
| skills | 業務手順書 |
| commands | ワンクリックの指示書（例：`/weekly-journal`） |
| templates | 毎回ゼロから作らない型 |

**あなたが日常で触るのは主に 01〜07**。`.cursor` は裏で AI が参照する。

## 「企画」とは（講義での意味）

ジャーナル上の自分理解：**企画 ≒ 命名規則・ファイル名の統一**（Markdown 形式そのもの、という別解釈もメモにあったが、講義の主軸は **AI が一発で判別できる名前**）。

### 企画あり vs 企画なし

| | 企画なし | 企画あり |
|---|----------|----------|
| AIの動き | 中身を毎回丸読みして推測 | **場所とファイル名** で判断 |
| コスト | ファイルが増えると爆増しやすい | 最小限に近い |
| 精度 | ブレやすい | 安定しやすい |

例：`05_Outputs` に `Article - ○○.md` のように **種別が名前で分かる** 状態。

比喩：**雑草を抜く作業**が、実は土の肥料になる、と分かったときの世界観の変化——命名・整理も同系統の投資。整理をしなくても AI は探せるが、工程が増え **課金地獄** になりやすい。

## 講義のまとめ（締めのメッセージ）

- 高度な個人技ではなく、**精度とコストを構造で担保する**設計
- 一度乗ると：ファイル増加 → AI が賢く → 手直し減 → クレジット節約と精度向上が同時に回りやすい
- この先の操作も「なぜこうなっているか」で迷子になりにくい

**要確認（ジャーナル）**: 音声の誤変換候補（「表現感」→ ChatGPT Plus 等）は、動画で再確認。
