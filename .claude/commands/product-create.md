# /product-create — 商品企画 壁打ちワークフロー

商品（講座・プログラム・コース・教材）の企画から販売コンテンツまで、壁打ち形式で一緒に作り上げるコマンド。

## なぜこのコマンドが必要か

商品を作る時、普通にやると確実に以下が起きる：
- コンセプトが曖昧なまま台本を書き始めて手戻りが発生する
- 「誰に売るか」が途中でブレて全部作り直しになる
- 事前教育→セールス→販促の整合性が取れなくなる
- 抜け漏れに気づくのが販売直前

このコマンドは「壁打ち → 決定 → 次のPhase」のサイクルを回し、全工程の抜け漏れと手戻りをゼロにする。

## 前提条件

以下のコマンドを先に実行しておくと、壁打ちの精度が上がる（必須ではない）:
- `/setup-character` → あなたの人格・実績・ストーリーの設定
- `/setup-target` → ターゲット顧客の設定

## 全体マップ

```
Phase 0: 初期化 .............. フォルダ作成 + 方向性確認
    ↓
Phase 1: コンセプト壁打ち .... 何を・誰に・なぜ自分が
    ↓
Phase 2: 企画書作成 .......... 商品設計・カリキュラム・導線
    ↓
Phase 3: ナレッジ整理 ........ 一次情報の構造化・根拠追加
    ↓
Phase 4: 事前教育コンテンツ .. 動画台本・ボレット・誘導文
    ↓
Phase 5: セールスコンテンツ .. VSL台本 or セールスページ
    ↓
Phase 6: 特典・オファー設計 .. リストイン特典〜購入特典
    ↓
Phase 7: プロモーション ...... 販促コラム・メルマガ・興味づけ
    ↓
Phase 8: 商品本体 ............ 受講者に渡すコンテンツ
```

## 使い方

**新規スタート:**
```
/product-create
```

**途中から再開:**
```
/product-create Phase 4から再開
```
→ 企画書を読み込み、現在の進捗を確認してから指定Phaseに入る。

---

## 共通ルール

### 壁打ちの原則
1. **AIが先に叩き台を出す**。白紙から考えさせない
2. **音声入力がラフでも** AIが整理して確認を取る
3. **70%で次に進む**。完璧を目指さず、後からいつでも戻れる
4. **各Phase完了時にファイル保存** → 次のPhaseを案内

### 自動読み込みファイル（存在する場合）
- `.cursor/rules/my-business.mdc`（ビジネス設定）
- `03_Knowledge/` フォルダの関連ファイル
- 企画書ファイル（Phase 1以降で常に参照）

### 保存先
```
05_Outputs/{プロジェクト名}/
├── 企画書.md                    ← Phase 0で作成、以降更新し続ける
├── ナレッジ.md                  ← Phase 3
├── 事前教育動画① - 台本.md     ← Phase 4
├── VSL - 台本.md                ← Phase 5
├── セールス特典/                ← Phase 6
├── 販促コラム① - {タイトル}.md  ← Phase 7
└── {商品本体}/                  ← Phase 8
```

## Phase 1: コンセプト壁打ち

### 目的
**一文コンセプト** と **ターゲットプロフィール** を確定させる。

### AIの行動

#### Step 1-1: 背景の深掘り

my-business.mdc がある場合は読み込み、以下を質問:

```
テーマは「{テーマ}」ですね。

ここを深掘りさせてください。自由に話してもらえればOKです。

・このテーマで商品を作ろうと思ったきっかけは？
・最近このテーマで感じたこと、気づいたことは？
・このテーマで困ってる人を思い浮かべると、具体的にどんな人？
・既存の解決策（競合）の何が不満？
・あなたがこれを教える「資格」は何？（実績・経験・独自の視点）
```

#### Step 1-2: コンセプトの壁打ち

回答を整理し、一文コンセプトの候補を3つ提案:

```
あなたの話を整理しました。

【核心の問題】
{問題の本質を1文で}

【あなたの解決策】
{解決策の本質を1文で}

---

一文コンセプト候補:

A:「{候補A}」
B:「{候補B}」
C:「{候補C}」

どれが一番しっくりきますか？
「AとBを混ぜたい」「全部違う」等のフィードバックもOKです。
```

#### Step 1-3: ターゲットの具体化

```
次にターゲットを具体的にしましょう。

・レベル：（初心者 / 中級者 / 上級者）
・現在の状況：
・痛み：（何に困ってる）
・理想：（この商品の後、どうなってほしい）
・向かない人：
```

### Phase 1 完了時

企画書の「コンセプト」「ターゲット」セクションを書き込み。

---

## Phase 2: 企画設計

### 目的
企画書の全セクションを埋める。

### AIの行動

各項目でAIが先に叩き台を出し、ユーザーがフィードバックする。

#### Step 2-1: 問題定義
ターゲットが抱える本質問題を整理して提案。

#### Step 2-2: 解決の仕組み
なぜこの手段で解決できるか、他の手段ではダメな理由を整理。

#### Step 2-3: 商品設計
形式・期間・価格・含まれるものを提案。

#### Step 2-4: カリキュラム設計
期間に合わせたカリキュラムの骨格を提案。

#### Step 2-5: 販売導線設計
集客→教育→セールスの流れを提案:
```
集客（チャネル）→ リストイン（特典）→ 事前教育（動画N本）→ セールス（VSL/LP）→ 販促
```

### Phase 2 完了時

企画書の全セクションを書き込み。

---

## Phase 3: ナレッジ整理

### 目的
商品コンセプトの「源流」を構造化する。台本・セールス文の全ての土台になる。

### AIの行動

```
企画書の骨格ができました。

ここから、コンセプトの「源流」を深掘りします。
以下を自由に話してください（音声で10分くらいがベスト）:

・このコンセプトに辿り着くまでの思考プロセス
・このテーマで体験した具体的なエピソード
・「これだ！」と確信した瞬間
・このテーマの裏側にある哲学・信念
```

回答を構造化して `ナレッジ.md` に保存:
- 原文（生の言葉そのまま）
- 思想の構造分析
- コンセプトへの接続
- 教育・セールス向け切り口表
- 論理的補足（根拠・事例）

---

## Phase 4: 事前教育コンテンツ

### 目的
事前教育動画の台本を壁打ちで作成する。

### AIの行動

各動画について:
1. **構成の壁打ち**: 目的・視聴者の状態変化・構成案を提案 → フィードバック
2. **台本の壁打ち**: 各セクションを順に執筆 → セクションごとにフィードバック
3. **ボレット・誘導文**: 台本完成後、メルマガ/LINE用のボレットと誘導文を作成

---

## Phase 5: セールスコンテンツ

### 目的
VSL台本またはセールスページを作成する。

### AIの行動

Phase 4と同様の壁打ち流れ。セールス要素（価格提示・特典・反論処理・CTA）を含む構成で作成。

---

## Phase 6: 特典・オファー設計

### 目的
ファネルの各段階で渡す特典を設計する。

### AIの行動

```
特典を設計しましょう。

【リストイン特典】登録の動機づけ
【教育間特典】エンゲージメント維持
【早期申込特典】即決の後押し
【商品内特典】成果の加速

各段階でどんな特典を用意したいですか？
アイデアがあれば教えてください。なければ提案します。
```

---

## Phase 7: プロモーション

### 目的
promotion-config を作成し、全配信ファイルを一括生成。その後、各ファイルを壁打ちで執筆する。

### AIの行動

#### Step 7-1: プロモーション計画の壁打ち

```
プロモーションを設計しましょう。

企画書のセールス期間は{N日間}ですね。
以下の全体設計を提案します。

【事前教育期間（3〜5日）】
・事前教育メール（問題認識・価値観シフト）
・動画案内メール
・教育コラム

【企画案内（1日）】
・VSL案内メール
・教育仕上げメール

【セールス期間】
・受付開始メール
・セールス教育（FAQ・比較・実績）
・カウントダウン
・最終日メール

【追加チャネル】
・LINE配信: {有 / 無}

この計画でOKですか？
配信通数の増減など変更があれば教えてください。
```

#### Step 7-2: Promotion Config の作成

計画が確定したら、`.cursor/templates/promotion/promotion-config.md` をベースに config ファイルを作成:

```
promotion-config.md を作成します。

以下の情報を教えてください（わかる範囲でOK。後から変更できます）:

・セールス開始日（予定）:
・受付最終日:
・VSLページURL（未定なら後で）:
・YouTube動画のURL（未定なら後で）:
・プラン名と価格:
```

回答を元に `05_Outputs/Products/{商品名}/promotion-config.md` を生成・保存。

#### Step 7-3: /promotion-scaffold の実行

```
config が完成しました。全配信ファイルを自動生成します。

/promotion-scaffold を実行してよいですか？
```

scaffold を実行し、全スケルトンファイルを生成。

#### Step 7-4: 各ファイルの執筆

生成されたスケルトンを壁打ちで執筆。推奨の執筆順:
1. 受付開始メール ← セールスの核
2. VSL案内メール ← セールスへの橋渡し
3. 事前教育メール ← 連番順に
4. セールス期間メール ← 連番順に
5. LINE・特典

### Phase 7 完了時

promotion-dashboard.md で全ファイルのステータスを確認。
全て完成になったらチェックリスト更新。Phase 8 へ案内。

## Phase 8: 商品本体

### 目的
受講者に実際に渡すコンテンツを作成する。

### AIの行動

カリキュラムに沿って、テキスト・ワークシート・テンプレート・ガイド等を作成。

---

## 途中再開時の動作

`/product-create Phase Nから再開` が実行された場合:

1. 企画書ファイルを読み込む
2. 進捗チェックリストを確認
3. 完了済みPhaseの要約を表示
4. 指定Phaseの冒頭から開始

```
企画書を読み込みました。

【現在の進捗】
✅ Phase 0〜2: 完了
⬜ Phase 3: ← ここから

Phase 3（ナレッジ整理）から始めます。
```
