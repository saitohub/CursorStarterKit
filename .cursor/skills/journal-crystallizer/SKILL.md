# Journal Crystallizer スキル

ジャーナルを読み込み、**内省分析→気づき自動追記→知識資産の抽出→深掘り質問→保存**を行うスキル。  
「/weekly-journal」または「/monthly-journal」コマンドで起動する。

---

## Cursor 3 以降の運用方針

このスキルは、Cursor 3 以降の Agents Window / `/multitask` / async subagents を前提に運用してよい。

ただし、ジャーナルは利用者本人の一次情報なので、**原文収集・気づき追記・保存処理は必ず親エージェントが最終確認する**。
サブエージェントは探索・分析・候補抽出に使い、ファイルへの最終書き込み判断は親エージェントが担う。

### 並列化してよい処理

- 週次・月次ジャーナルの対象ファイル確認
- `03_Knowledge/` 既存ファイルとの重複チェック
- Story / Logic / Evidence / Claim 候補の洗い出し
- 内省分析の視点候補出し
- 過去の週次・月次振り返りとのテーマ比較

### 直列で行う処理

- ジャーナル原文の収集結果確定
- チェックボックス番号の採番
- `06_Reflections/` への保存
- `03_Knowledge/` への新規作成・更新
- ユーザーに確認が必要な分岐

### `/multitask` 使用時の分担例

月次ジャーナルのように対象量が多い場合は、必要に応じて以下のように分担する。

- 収集担当: 対象期間の素材収集・タグ別整理。書き込みはせず、親エージェントが保存する
- 内省担当: 内省テーマ・気づき候補の分析。書き込みはせず、親エージェントが追記する
- 親エージェント: 重複チェック・採番・保存・ユーザー確認を担当する

並列化した場合でも、最後に親エージェントが結果を統合し、重複・番号・タグ表記を確認してから保存する。

---

## このスキルがやること

1. **収集**: 指定期間のジャーナルを全て読み込み、感情タグを分類する
2. **内省分析 + 気づき追記**: フィードバックを生成し、得られた気づきをジャーナルに自動追記する
3. **深掘り抽出**: 03_Knowledge に入れる候補（Story/Logic/Evidence/Claim）を抽出し、Q1/Q2の深掘り質問で内容を濃くする
4. **保存**: 振り返りを `06_Reflections/` に保存し、答えてもらった候補はKnowledgeファイルとして自動作成する

---

## Step 1 ｜ジャーナルの収集

コマンドで渡されたパラメータを確認する。
月次など対象量が多い場合は、先に対象ファイル一覧だけを確認し、必要に応じて `/multitask` で収集・既存振り返り確認・重複チェックを並列化する。

- `timeframe: weekly` → 直近7日分のジャーナルを `04_Journals/` から読み込む
- `timeframe: monthly` → 直近30日分のジャーナルを `04_Journals/` から読み込む

ファイルが見つからない場合は「〇〇〜〇〇の期間のジャーナルが見当たりません。04_Journalsフォルダに日付形式（YYYY-MM-DD.md）でファイルが入っているか確認してください」と伝える。

### 感情タグの認識

ジャーナル内に以下のタグがある場合、感情カテゴリとして認識し、フィードバックの精度を上げる。

| タグ | カテゴリ |
|-----|---------|
| #💡 | 閃いたこと |
| #😍 | 嬉しかったこと |
| #🔥 | 燃えた・やる気が出たこと |
| #😭 | 悲しかったこと |
| #😡 | 怒ったこと |

タグがなくても処理は正常に進む。タグは「あるとフィードバックの精度が上がるもの」であり、必須ではない。

### 音声入力スペース整形

音声入力で書かれたジャーナルに不自然なスペース（単語間のスペース挿入、行頭の余計なスペース等）がある場合、読み込み時に自動で整形する。内容・感情表現・文体は一切変更しない。

読み込んだら「〇件のジャーナルを読み込みました。処理を開始します」と一言だけ伝えて次に進む。

---

## Step 2 ｜内省分析 + 気づき自動追記

### 2.1: フィードバックの生成

以下の構成でフィードバックを生成する。  
`references/feedback-guide.md` のトーンガイドを必ず参照して書くこと。
分析はサブエージェントに任せてよいが、追記する気づきの選定・採番・書き込みは親エージェントが行う。

**① 今期のあなたへ（全体の一言）**  
この期間全体を見渡した時、一番印象的だったことを1〜2文で伝える。  
評価・採点ではなく「あなたはこういう期間を過ごしていた」という観察として書く。

**② 前進したこと・動いたこと**  
ジャーナルから「行動した記録・試みた記録」を拾い上げる。  
小さなことでいい。「やろうとした」も前進に含める。  
箇条書きで3〜5個。

**③ 繰り返し出てきたテーマ・感情**  
複数のジャーナルに共通して出てきたキーワード・感情・問いを抽出する。  
感情タグ（#💡 #😍 #🔥 #😭 #😡）があれば、タグの分布パターンも示す。  
「こういうことが気になっているんですね」という観察として伝える。  
ここは評価せず、ただ「パターンを見せる」だけにする。

**④ 自分への問いかけ（次の期間に持っていく1問）**  
この期間のジャーナルを踏まえて、次に向かうための「問い」を1つだけ出す。  
答えを押し付けない。問いの形で終わる。  
例：「あなたが一番エネルギーを感じた瞬間は、どんな状況でしたか？」

### 2.2: 気づきの自動追記

フィードバック生成後、得られた気づきをジャーナルファイルに**チェックリスト形式で自動追記**する。

**追記形式:**
```markdown
---

## 内省から得られた気づき（#🔮）

- [ ] {ファイル全体の最大番号+1}. 【内省分析】{気づき1}
- [ ] {ファイル全体の最大番号+2}. 【内省分析】{気づき2}
```

**番号付けルール（絶対遵守）:**
- 追記前に必ずファイル全体（`- [ ]` と `- [×]` の両方）をスキャンして最大番号を特定する
- 番号重複禁止
- 気づきは2〜4個。多すぎない

**⏸️ ここで停止**: 追記完了を報告し、「Step 3（Knowledgeの深掘り抽出）に進みますか？」と確認する。

---

## Step 3 ｜深掘り抽出（Q1/Q2フレーム）

ジャーナル全体を読み返し、Knowledge候補を抽出する。

### 3.0: 候補の抽出

以下の基準で候補を抽出する：

**Story候補**  
→ 自分が体験したこと・感情が動いたこと・失敗や成功の記録が含まれているジャーナル。  
　 具体的なエピソードがあれば候補にする。

**Logic候補**  
→ 「なぜこうなるか・どういう仕組みか・自分はこう考える」という思考の流れがあるジャーナル。

**Evidence候補**  
→ 「誰かの言葉・データ・歴史的事実・外部の根拠」が引用・言及されているジャーナル。

**Claim候補**  
→ 「〜すべき・〜は間違い・〜が本質だ」という断言・主張・価値観が出ているジャーナル。

### 3.1: 既存ファイルの重複チェック（必須）

候補を提案する**前に**、既存ファイルを検索して重複を防ぐ。
ここはCursor 3以降では並列化してよい。Story / Logic / Evidence / Claim を別々に確認してもよいが、最終判断は親エージェントが統合する。

```
03_Knowledge/Story/Story - *.md
03_Knowledge/Logic/Logic - *.md
03_Knowledge/Evidence/Evidence - *.md
03_Knowledge/Claim/Claim - *.md
```

類似するファイルがあれば「更新 / 新規作成 / スキップ」の選択肢を提示する。

### 3.2: Q1/Q2 深掘り質問

各候補に対して**2問セット**で提示する。1候補につき2問を超えない。

```
---
📖 Story候補｜「初めてメルマガ反応ゼロだった日」
> ジャーナル 2026-XX-XX より
一言：初めてメルマガを配信して反応がゼロだった体験が書かれている。

💬 Q1（場面を教えてください）
「その時の場面を映像で切り取るとしたら、何が見えますか？
 いつ、どこで、何があって、最初に気づいた瞬間は？」

💬 Q2（エネルギーの動きを教えてください）
「その体験の間、自分の中のエネルギーはどう動きましたか？
 高まった？沈んだ？どこかで反転した？」

Q1だけでも、両方でも、答えなくてもOK。答えた分だけ内容が濃くなります。

---
🧠 Logic候補｜「感覚型ビジネスが再現できない構造的理由」
> ジャーナル 2026-XX-XX より
一言：なぜ感覚で動くビジネスが安定しないかの理由を考察している。

💬 Q1（きっかけの体験を教えてください）
「この考えに最初に気づいたのは、どんな具体的な出来事がありましたか？
 誰かとの会話？自分の失敗？何かを読んだ瞬間？」

💬 Q2（誰に伝えたいかを教えてください）
「この考えを一番聞かせたい人はどんな人ですか？
 または、過去の自分のどの時点に届けたいですか？」

Q1だけでも、両方でも、答えなくてもOK。答えた分だけ内容が濃くなります。
---
```

#### 種類別の問い設計

**Story候補の場合：**
- Q1：「その時の場面を映像で切り取るとしたら、何が見えますか？（いつ、どこで、何があった？）」
- Q2：「その体験の間、自分のエネルギーはどう動いていましたか？高まった・沈んだ・途中で変わった？」

**Logic候補の場合：**
- Q1：「この考えに最初に気づいたのは、どんな具体的な出来事がきっかけでしたか？」
- Q2：「この考えを誰かに話した時、相手の反応はどうでしたか？または、一番伝えたい人は誰ですか？」

**Claim候補の場合：**
- Q1：「この主張を持つ前の自分は、どう考えていましたか？何がきっかけで変わりましたか？」
- Q2：「この主張を聞いて反発しそうな人がいるとしたら、どんな人で、なぜ反発すると思いますか？」

**Evidence候補の場合：**
- Q1：「このデータ・言葉に出会ったとき、最初にどんな反応がありましたか？」
- Q2：「これを自分のビジネス・コンテンツのどんな場面で使いたいですか？」

#### 共通ルール

- Q1は必ず具体・場面レベルで聞く（抽象的な「なぜ？」は避ける）
- Q2はQ1の答えを受けて自然に深まる流れにする
- 末尾に「Q1だけでも、両方でも、答えなくてもOK。答えた分だけ内容が濃くなります」と一言添える
- 圧をかけない。「もし話せるなら」のトーンを保つ

### 3.3: 回答の受け取り

質問を提示した後、以下を伝える：

```
---
答えたいものだけ答えてください。全部答えなくて大丈夫です。
「保存して」と言ってもらえれば、答えた内容を反映して保存します。
```

ユーザーが「保存して」と言ったら Step 4 に進む。

---

## Step 4 ｜保存

### 4.1: Knowledgeファイルの作成

答えてもらった候補を、対応するテンプレートで保存する：

| 種類 | 保存先 | テンプレート |
|------|--------|------------|
| Story | `03_Knowledge/Story/Story - {タイトル}.md` | `02_Configs/Templates/Template - Story.md` |
| Logic | `03_Knowledge/Logic/Logic - {タイトル}.md` | `02_Configs/Templates/Template - Logic.md` |
| Evidence | `03_Knowledge/Evidence/Evidence - {タイトル}.md` | `02_Configs/Templates/Template - Evidence.md` |
| Claim | `03_Knowledge/Claim/Claim - {タイトル}.md` | `02_Configs/Templates/Template - Claim.md` |

- Q1の回答 → 「いつ・何があったか」「きっかけの体験」等のセクションに反映
- Q2の回答 → 「エネルギーの動き」「誰に伝えたいか」等のセクションに反映
- 答えなかった候補は振り返りファイルの「未作成候補」に残す

### 4.2: 振り返りファイルの保存

- 週次：`06_Reflections/Weekly/Reflection - YYYY-WW週.md`
- 月次：`06_Reflections/Monthly/Reflection - YYYY-MM.md`

**振り返りファイルの構成：**

```markdown
---
date: YYYY-WW（または YYYY-MM）
type: weekly-reflection（または monthly-reflection）
period: YYYY-MM-DD 〜 YYYY-MM-DD
---

## 今期のあなたへ
（Step 2で生成したフィードバックの要約）

## 前進したこと

## 繰り返し出てきたテーマ

## 次の期間に持っていく問い

---

## 作成済みKnowledgeファイル
- [[Story - 〇〇]]
- [[Logic - 〇〇]]

## 未作成候補（答えなかったもの）
（未回答の候補をリスト形式で残す）
```

### 4.3: 完了報告

```
✅ 振り返りが完了しました。

保存した場所：
・振り返りファイル → 06_Reflections/[Weekly or Monthly]/
・Knowledgeファイル → 03_Knowledge/（X件）

未作成の候補（X件）は振り返りファイルに残してあります。
気が向いたときにファイル化してください。
```

---

## 最重要事項

1. **原文厳守**: ジャーナルの原文は維持する（音声スペース整形のみ許可）
2. **番号重複禁止**: 気づき追記の番号は、ファイル全体の最大番号の次から開始
3. **Q1/Q2は2問まで**: 深掘りは1候補につき2問を超えない
4. **重複防止**: Step 3では**提案前に必ず既存ファイルを検索**
5. **タグのバリアント生成禁止**: `#💡` `#😍` `#🔥` `#😭` `#😡` はObsidianのタグとして機能する。`#💡①` のような派生タグを絶対に作らないこと。見出しや参照では `💡①`（`#` なし）にする
6. **Step 2で必ず停止**: 気づき追記後、Step 3に進むかユーザーに確認する
7. **07_Swipe は参照しない**: Swipeフォルダは他人の事例集であり、Knowledge抽出の対象外。ジャーナル（04_Journals）からのみ抽出する
