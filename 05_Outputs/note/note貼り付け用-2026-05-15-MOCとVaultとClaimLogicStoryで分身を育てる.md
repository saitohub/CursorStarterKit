# ジャーナルがそのまま死なない：地図（MOC）と置き場で、伴走AIを「自分の基準」に寄せる

**サイジム**｜会社員。noteで発信しながら、CursorとObsidianでメモ環境を育てています。

**【noteに貼るとき】** このファイルは、表（`|`）とコードフェンス（\`\`\`）をやめてあります。それでも崩れるときは、note側の「リッチ／マークダウン」表示を一度切り替えるか、**小さい塊に分けて貼る**と通りやすいです。

## 今日の話の前提

「AIで分身をつくる」みたいな言い方は、聞こえはいいんだけど、正直いちばんつまずくのはそこじゃない、という感覚があります。

つまずくのはだいたい、ここだと思っています。

- 学びはその日はわかった気になるのに、**翌日には場所が思い出せない**  
- フォルダを増やしたはいいが、**どこに何を置いたか自分が説明できない**  
- AIに長文を渡すと、**それっぽい答えは返るのに、自分の文章じゃない**

この記事は、派手なプロンプト集ではなく、**地図（MOC）と置き場の設計**と、**ファイルの役割分け（Claim / Logic / Story）**の話です。  
根拠にするのは、僕が2026年5月に自分のVaultでやった作業ログと、そのあとに残した判断メモです。

## なぜ「分身」より先に、地図と置き場なのか

「分身」って言葉、ゴールとしてはわかる。  
でもゴールが遠いと、手が止まる日が来る。僕の場合は、**遠い山を見すぎるほど、足元の整理が後回し**になりやすいタイプです。

だから順番を入れ替えました。近い山はこれ。

1. **迷子にならない地図**（テーマの入口＝MOC）  
2. **腐らない置き場**（日次・資産・出力・振り返りの役割分担）

この2つがそろうと、AIに渡す材料の単位が小さくなる。単位が小さくなると、「それっぽい」から**「あなたの基準に寄る」**に寄りやすい。  
これは気合いの話じゃなくて、僕の体感としては**設計の話**に近いです。

## MOCって、結局なに？

MOCは **Map of Content** の略で、テーマごとにリンクを集めた **ハブ／目次ノート** みたいなもの、と理解しています。

Wikiの目次とも違う気がしていて、僕の中では **「今週いちばんよく開く入口」** 寄りです。  
僕のVaultだと、学習中の講座メモの入口に、MOC用のノートを1枚置いています（Obsidianなら、そのノートから各メモへリンクで辿るイメージ）。

ここで大事にしているのは、知識の定義を完璧に書くことより、**入口を1つに固定する**こと。  
新しい用語が出た日は、チャットで意味を聞いて、**その日のジャーナルに1ブロック逃がす**。これが僕の自分ルールです。  
「調べた」で終わらせず、**日付つきのログに落ちたか**が、あとから効いてきます。

## Vaultの置き場は、役割で切る

人によってフォルダ名は違うと思うので、名前は各自でよくて、僕はざっくりこういう役割で切っています。

- **日次の生** … 感情も事実も含めたジャーナル。整わなくてOK  
- **言語化が終わったもの** … 主張・手順・体験を、後から再利用できる形にしたノート  
- **読者向けの完成品** … noteの下書き、プロフィール文、配布物の原稿  
- **振り返り** … 週次・月次で、方向のズレを直すメモ  

ここで僕が意識しているのは、**どこか1つは「荒れてOK」ゾーンを許す**ことです。  
全部きれいにしようとすると、きれいにする作業が仕事になって、本題が進まない。  
荒れてOKを決めると、続く、というのは僕の経験則に近いです。

## フォルダは「意味の単位」で増やす

2026-05-14に僕がやったのは、学習中の講座メモのフォルダを、頭の中の並びに寄せて **「第1項」「第2項」** みたいな単位に寄せ直す、という作業でした（※項番号は、自分の頭の整理に合わせた名前で、講座公式の用語そのものではありません）。

FinderでもCursorでもリネームはできるし、Obsidianはノート同士のリンクが多いので、親フォルダ名が変わってもリンクが切れにくい、というのが根拠でした。

ただしここでいちばん大事だったのは、整理そのものより **確認** でした。

カバーノートの見出しが、別の講義ノートと似ていて、リンクもついていた。  
「講座の公式ルールでそうなってる？」と聞いたら、**自分のワークスペースのルールとして義務ではない**、という整理になりました。AI側の「揃えやすさ・辿りやすさ」の判断だった、ということ。

つまり、**AIが整えてくれた形は、そのまま正解の運用だと思い込まない**。  
気になったら「ルール化されてる？」と一言確認する。これだけで、Vaultの主権は戻ってきます。

フォルダが増えすぎるときは、僕はジャーナルにこう書いて自分にツッコミました。  
「いっぱい入れてもわかんねえよ」。だから **増やすなら3軸くらいに寄せる** 方向で考え直す、が現実的でした。

## Claim / Logic / Story に分けると、何が楽になるか

ここは名前が難しそうに見えるんだけど、中身は地味で、**混ぜないための仕切り**です。

- **Claim**：主張。外に出すなら、一番大事な約束の芯。  
- **Logic**：手順や構造。再現したいならここが厚い。  
- **Story**：体験のシーン。読者が自分事にしやすい材料。  
- **Evidence**：出典や一次確認のログ。最初から完璧じゃなくていい。空欄で始めてもいい。

僕が止まりやすいパターンは、**主張と手順と体験が1枚に混ざる**ことでした。混ざると、AIに渡すときも自分で読み返すときも、編集対象が増えすぎる。

だから **1入力につき1出力** を、ルールに近い形で持っています。  
いまの入力は「主張を磨く日」なのか「手順を書く日」なのか、先に決める。これだけで、伴走の質が変わることがあります。

## Cursorは「整理係」じゃなくて「伴走の編集者」

僕の使い方の中心は、文章を丸投げして神回答を待つ、ではなくて、

- 用語を聞いたら **ジャーナルに定義を残す**  
- リネームやリンク直しを頼むときに **「ルール化されてる？」を確認する**  
- 長文を一気に食わせるより、**分割して読ませる**

に寄せています。  
分割して渡せるようになると、Claim / Logic / Story みたいな仕切りが、ツール上のメリットにもつながります。

## 「ここが違う」が増えるほど、分身は育つ

僕の体感だと、分身が育ち始めたサインは、かっこいい成果より先に来ます。

**AIの出力に対して「ここが違う」「そうじゃねえんだよ」と言葉にできる回数が増える**こと。  
言葉にできたものは、ルールやメモとして残せる。残せると、次のチャットが楽になる。

画像や動画より、僕はいまのところ **文字と、音声から起こしたテキスト** を優先して食わせる方針です。理由はシンプルで、コストと再現性のバランスが取りやすいから。  
これは正解宣言じゃなくて、僕の現時点の運用です。

## noteで公開する人への安全策（一次確認）

AIの文章は、そのまま貼ると事故りやすい。僕が自分用に持っている型は、ざっくりこれです。

1. **引っかかり**を記録する（違和感、笑い、モヤモヤでもいい）  
2. **一次確認**（固有名、数字、引用はできる範囲で原典に寄せる）  
3. **文脈まで**（誰に向けた言葉か、いつの話か）  
4. **自分のレーンへ**（「書いた」と「確かめた」を分ける）

公開する文字ほど、確認は神経質じゃなくても、**コスト対効果で効く**場面があります。
