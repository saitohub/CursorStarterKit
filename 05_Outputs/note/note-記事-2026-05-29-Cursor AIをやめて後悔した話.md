# Cursor AIをやめたら、後悔した話。～3週間後、その理由が変わった～

新しいツールに乗り換えると「困った」と感じます。ターミナル、音声認識、細かい確認…。

でも 3 週間経った今、その困りごとが実は「成長の種」だったことに気づきました。

以下は、Cursor AI から Claude Code に乗り換えた私が、3 週間で経験したリアルな振り返りです。

---

## 正直に言う。困ったことが山ほど出た。

**① エラーのたびにMacのターミナルを立ち上げないといけない**

Cursor内のターミナルではなく、Mac本体のターミナルを開いてシステムを操作しないと解決できないエラーが頻発した。

最初は何が起きているかすらわからなかった。

**② 音声で入力した文章の整形が、Cursor AIより遅い**

話した内容を貼り付けて「整えて」と頼んでも、なんとなく時間がかかっている気がする。

体感だが、Cursor AIの方がサクサクしていた。

**③「続けていいですか」が頻繁に出てくる**

10行くらいの文章を渡すと、途中で止まって確認してくる。

これが煩わしかった。

ただ、「途中で聞いてくるのをやめてほしい」と一言伝えたら、以降は出なくなった。

**④ たまにチャットが打てなくなる**

突然、文字が入力できなくなることがある。

Escキーを押すと直る。でも、なぜ打てなくなったのか画面を見ても全くわからない。

ヒントらしきものが出ているらしいが、気づけないレベルの小ささだ。

「とりあえずEsc」で覚えるしかない。

**⑤ セキュリティと削除が怖い**

API接続のパスワード設定など、少し危険を感じる場面があった。

削除系の依頼をするときも、正確に指示を出さないとどこまで消すかわからない。以前、セキュリティ関連で実際にヒヤリとしたことがあった。

---

## それでも使い続けている理由

Cursor AIとClaude Codeは、**できることが根本的に違う。**

Cursor AIは「書きながら相談する」ツール。

Claude Codeは「結果だけ言って丸投げする」ツール。

この違いを理解してから、使い方を変えた。

---

Cursor AI時代の頼み方

> この段落の2文目を短くして

Claude Codeの頼み方

> この記事全体をテンポよく読めるように整えて

---

細かく指示するのではなく、**完成イメージだけ渡す。**

そうすると、自分では1時間かかる作業が数分で終わる。

複数のファイルをまたぐ大きな変更や、スクリプトの実行なども一発で動く。

Cursor AIが苦手だったことが、Claude Codeは得意だった。

---

## 3週間後、あの困ったことはどうなった？

5月29日にこの記事を書いてから、3週間が経ちました。

あの「困ったこと」たちは、本当に困ったままなのか。それとも…？

実際に起きたことを、率直に振り返ります。

### 新しいツール = 困る、という心理

最初、Claude Code を使って感じたのは「なんか使いづらい」という感覚。

これは、実は Cursor AI に「慣れてた」ことが大きかったんだと気づきました。

新しいツール＝困る、ではなくて、**「使い方をまだ知らない」**が正体。3週間で理解が進むと、困りごとは減ります。

**今、新しいツール乗り換え時に困ったら：** 「困ったことメモ」を毎日つけて、何が「慣れ」で何が「本当の欠陥」かを分ける。3週間でパターンが見える。

### Mac のショートカットに慣れた

Windows ユーザーだったので、Mac の Command キー操作が最初、すごく煩わしかった。

でも **3週間で普通になりました。**

最初は 1 回のショートカットに 2 秒かかってた（「あ、Command + V だった」と思い出す時間）→ 今は意識せずに動く。

こういう小さな「慣れ」の積み重ねが、実は大きな生産性改善だったんだと気づきます。

**今、ショートカット覚えるなら：** よく使う操作を 1 週間で 5 回繰り返す。2 週目には無意識に動くようになる。

### 音声認識の精度が、思った以上に上がってた

当初、「音声入力した文章の整形が遅い」と感じていた理由は、実は **音声認識の精度が低かった**から。

かつての Aqua Voice では、1 分の音声に誤字脱字が 5～10 個混じってました。整形に 5～10 分。

今は精度が上がって、整形は 1～2 分。

これは、AI 技術の進化です。自分が何か悪いわけじゃなくて、テクノロジー側が進化してた。

**今、音声で記事書くなら：** 音声認識が 80%の精度でいいと割り切る。完璧を狙わない。20%の手直しで十分。

### 「続けていいですか」が、実は成長の機会だった

最初、すごく煩わしいと感じてました。10 行書くと「続けていいですか」って聞いてくる。

でも 3 週間経つと、その「確認」が実は **「思考のチェックポイント」** だったことに気づきました。

- セキュリティ意識が高まった
- AI に全部任せず、自分で理解しながら使う習慣がついた
- AI の仕組みが勝手に身についた

最初の苛立ちは、実は「学習への入口」だったんです。

**今、AI を使うなら：** 「続けていいですか」と聞かれたら、ここが勉強ポイント。「なぜこの選択肢？」と逆質問する。AI の思考が見える。

### 英語の嫌悪感が、いつの間にか学習に変わってた

システムメッセージが英語で出てくるのが嫌でした。大学受験以来、英語やってないし。

でも、その経験があったおかげで、AI がなぜそのエラーを出してるのか、どういう意図の警告かが理解できるようになりました。

辞書なしで「AI の意図」を学べる環境。これは、実は很强い学習機会。

**今、AI のエラーが英語で出たら：** 辞書の代わりに、「AI は何を言ってる？」を考える。その答えがわかると、次似た場面で対応できる。

---

## 困ったことの多くは「伝え方」で解決した

「途中で確認してくるのをやめて」と言えば止まる。

「削除する前に確認して」と言えば確認してくれる。

AIに対して、**働き方のルールを最初に伝える感覚**が必要だった。

Cursor AIは気を利かせてくれる同僚。

Claude Codeは、指示通りに動くスタッフ。

どちらが良い悪いではなく、**使い方が違う。**

---

乗り換えで後悔した。

でも使い方を変えたら、後悔が消えた。

ツールが悪いのではなく、使い方が間違っていただけだった。

---

Cursor AIに慣れている人が乗り換えるなら、**一度腕まくりをしてから臨む**ことをおすすめする。

Claude Codeの使い方を解説したYouTube動画を何本か見てから始めると、最初の「なんでこんなにやりにくいんだ」が減る。

勢いだけで乗り換えると、自分のように後悔する。

---

## 今日の一手

次にAIに何か頼むとき、「どうやって」ではなく「何がほしいか」だけ言ってみる。

それだけでいい。
