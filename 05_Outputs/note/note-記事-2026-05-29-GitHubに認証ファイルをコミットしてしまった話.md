こんにちは。サイジムです。

先に言っておくと、今日は失敗談です。
しかもわりと恥ずかしい系の。

---

GitHubにpushしようとしたら止まった。

> Push cannot contain secrets — Google OAuth Access Token detected

「シークレットが含まれてるのでpushできません」ってエラー。
GitHubのセキュリティ機能が弾いてきた。

最初、意味がわからなかった。
「secrets？どこに？」みたいな。

読み進めると、`token.json` にGoogleのアクセストークンが入ってると書いてある。

あ。

ObsidianのVaultをまるごとGitでバックアップしてるんですが、そのルートにGmail API用の認証ファイルを置いてた。
何ヶ月も、ずっと、コミットされ続けてた。

---

なぜ今まで気づかなかったか。

AIと一緒にPythonスクリプトをいじってて、「よし動いた」でそのままpushしたから。
確認を飛ばして、ポンポン進めてたんです。

ここで気づいたのが「APIの認証ファイルも個人情報だ」ということ。

`token.json` があればGmailにアクセスできる。
`client_secret_*.json` が漏れると、他人が自分のGoogle APIを使える。

名前や住所と違って、ファイルを見てもそうは見えない。
だから甘く見てた。

今やっていることが「何と同じか」を考えながら覚えていかないと、またやる。
パスワードをメモしてDropboxに置くのと、本質は同じなんですよ。

---

直し方はシンプルでした。

まず `.gitignore` に追記。

```
token.json
client_secret*.json
```

ただこれだけだと「今後は無視する」だけで、過去のコミットには残ったまま。
GitHubはpushされる全コミットをスキャンするので、1個でも残ってれば弾かれる。

なので `git filter-branch` で未pushの8コミットから丸ごと削除して、`git push --force` で完了。

一回で終わればよかったんですが、`token.json` を消してpushしたら次は `client_secret_*.json` で弾かれた。
2回やる羽目になりました。最初にまとめて確認すればよかった。

認証ファイルはVault外の `~/secrets/gmail_api/` に移動して、スクリプトの参照先も変更。
これで以後は混入しない。

---

そういえばCursorからClaude Codeに移行中なんですが、最初のうちって操作のたびに確認が出てくるんですよ。

「これ実行していいですか？」
「これは？」
「これも？」

正直、最初は煩わしかった。
だから「こういうのは全部やっていいよ」と権限設定を入れながら進めてた。

でもこの事故を経験して、少し見方が変わった。

「全部OKにする前に、本当に全部OKなのか」を考える機会がそこにあった。
自分は今回、その確認を飛ばしたから詰まった。

AIと一緒だと速く動ける。
速く動けるほど、何を渡してるかを意識しておく必要がある。

---

まとめると一行で済む話で、

**`.gitignore` を最初にちゃんと設定しておけばよかった。**

それだけです。
