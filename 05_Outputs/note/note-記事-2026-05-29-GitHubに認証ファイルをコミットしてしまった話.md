やらかした。

GitHubにpushしようとしたら、こんなエラーが出て弾かれた。

> Push cannot contain secrets — Google OAuth Access Token detected

「シークレット（機密情報）が含まれているのでpushできません」という意味だ。GitHubのセキュリティ機能「Push Protection」が作動したのだ。

正直、最初は何のことかわからなかった。「secrets？どこに？」という感じ。エラーメッセージを読むと、`token.json` の1行目にGoogleのOAuthトークンが含まれていると書いてある。

そこで気づいた。GmailのAPIを使うPythonスクリプトのために認証ファイルをVaultのルートに置いていた。ObsidianのVaultはまるごとGitで自動バックアップしている。つまり、認証ファイルが何ヶ月もずっとコミットされ続けていたのだ。

原因はすぐわかった。ObsidianのVaultをGit管理していて、自動バックアップが走るたびにルートに置いてあった認証ファイルも一緒にコミットされていた。今回はそれがGitHubに届こうとして、初めてブロックされた。

この記事では、何が起きたか・どう直したか・今後どう防ぐかを書いておく。

## 何が起きていたか

### 問題のファイル2つ

Gmailのメールを自動取得するPythonスクリプトを使っている。そのスクリプトを動かすためにGoogle APIの認証ファイルが必要で、2種類のファイルをVaultのルートに置いていた。

- **`token.json`** — Googleへのアクセストークン。有効期限があるが、中身は本物の認証情報
- **`client_secret_*.json`** — Google OAuthのクライアントID・シークレット。これが漏れると第三者が自分のGoogle APIを使える

両方とも `.gitignore` に書いていなかった。だから自動バックアップのたびに、何ヶ月もずっとコミットされ続けていた。

### なぜ今まで気づかなかったか

リモートリポジトリ（GitHub）はプライベート設定にしていた。プライベートなら外部から見えないので、致命的な被害は出ていない。

ただ、今回ローカルで8コミット分が積み上がっていた。それをまとめてpushしようとしたタイミングで、GitHubのPush Protectionが「このコミット群の中に機密情報がある」と検知してブロックした。

## どうやって直したか

### 手順1：`.gitignore` に追記

まず再発を防ぐために `.gitignore` に以下を追加した。

```
token.json
client_secret*.json
```

これで今後は自動バックアップに含まれなくなる。

ただし、`.gitignore` に追加しても**すでにコミット済みのファイルはgitの追跡から外れない**。「今後は無視する」という設定であって、過去を消す設定ではないのだ。ここを勘違いしていると、`.gitignore` に書いたのにgit statusに出てくる、という状況になる。過去のコミットから除去するには別の手順が必要だ。

### 手順2：git の履歴から除去

`.gitignore` に書いても、すでにコミット済みのファイルは履歴に残ったまま。GitHubはpushされる全コミットをスキャンするので、1つでも残っていれば弾かれる。

`git filter-branch` を使って、未pushの8コミット全部から `token.json` を除去した。

```bash
git filter-branch --force --index-filter \
  'git rm --cached --ignore-unmatch token.json' \
  HEAD~8..HEAD
```

これで「token.jsonを追加したことにする」コミットが書き換えられ、履歴上は存在しなかったことになる。

### 手順3：`client_secret_*.json` も同じ処理

pushしたら今度は `client_secret_*.json` でも弾かれた。同じ手順でこちらも除去。2回やる羽目になった。

> **反省点**：最初に `token.json` だけ消して「よし」と思ったのが甘かった。認証ファイルは複数あることが多いので、まとめて確認すべきだった。

### 手順4：認証ファイルをVault外に移動

再発防止のため、認証ファイルの置き場所をVaultの外に変えた。

```
~/secrets/gmail_api/client_secret_*.json
~/secrets/gmail_api/token.json
```

スクリプトのコードも参照先を変更。これでVaultをgit管理していても認証ファイルが混入しない。

### 手順5：force pushで完了

履歴を書き換えたので通常のpushではなく `git push --force` が必要だった。

```bash
git push --force origin main
```

これでGitHubのブロックが解除され、pushが通った。

## 今後やること

**`client_secret_*.json` の再発行を推奨**。今回はプライベートリポジトリだったので実害は出ていないはずだが、一度でもgitの履歴に入ったファイルは「漏れた可能性がある」と考えるべきだ。

Google Cloud Consoleで該当のOAuth認証情報を削除して新規作成すれば、古いキーは無効化される。

### Vault管理のリポジトリで気をつけること

ObsidianのVaultをGitでバックアップしている人は多いと思う。便利な反面、Vaultのルートに何でも置いてしまいがちで、今回のような事故が起きやすい。

特に注意が必要なファイルをまとめておく。

- **API認証ファイル**（`token.json`, `client_secret_*.json`, `.env`）
- **パスワードや秘密鍵を含むファイル**
- **個人情報が入ったCSVやスプレッドシート**

これらは最初から `.gitignore` に書いておくか、Vault外のフォルダに置くのが正解だ。自動バックアップは「全部まるごと」コミットするので、油断すると何でも上がっていく。

今回を機に `.gitignore` を見直すことをおすすめする。自分も今回やらかすまで、ちゃんと設定していなかった。

## まとめ

- **Vault（Obsidian）をGit管理しているなら、`.gitignore` の設定が最重要**
- 認証ファイルは最初からVaultの外に置く。`~/secrets/` などGit管理外のフォルダが安全
- やらかしても `git filter-branch` で履歴から消せる。ただしコミットのハッシュが変わるのでforce pushが必要
- プライベートリポジトリでも油断しない。いつパブリックに変えるかわからないし、GitHubのPush Protectionは止めてくれない

自動バックアップは便利だが、何でも全部コミットすると思わぬところで詰まる。`.gitignore` だけは最初にちゃんと設定しておくべきだった。
