# 「Cursor、壊れた？」と思ったら犯人は画面下——触り始めてハマった、タイピングだけもっさり問題

> 件名案（note公開用）：「Cursor、壊れた？」と思ったら犯人は画面下｜AIチャットは速いのにタイピングだけ重い  
> シリーズ：Cursor初心者・環境の罠（②タイピング遅延）  
> 構成：小林型（結論先出し→体験→着地）× ポンポン型（概念フック・ラベリング解除・疑う順番）ハイブリッド。  
> 事実：AIチャット欄は爆速／メインエディタだけワンテンポ遅れ。  
> 解決：ステータスバーの「スクリーンリーダーに最適化」をオフ → 一発で復帰。  
> 技術的原因は仮説ベース（断定しない）。

## 原因の核心：お節介機能のデッドロック（仮説）

なぜ重くなったのか。

​

ここからは **仮説** です。

断定はしません。

​

ただ、

体験と症状から見える **構図** は、

かなりはっきりしています。

​

**核心：**

**テキストを高速入力するAI** と、

**テキストを監視するエディタのお節介機能** が、

互いに足を引っ張り合った。

​

### 仮説1：音声AIの入力を、Cursorが「支援ソフト」と誤認

音声AI入力アプリは、

人が話した言葉を瞬時にテキスト化し、

​

クリップボード経由、

あるいは **超高速タイピングのような信号** として、

Cursorのエディタに流し込みます。

​

人間の手打ちでは、

あの速度は出ない。

​

Cursor側が

「普通の手動タイピングじゃない。

　これは **アクセシビリティ支援技術** が

　裏で自動入出力しているのでは？」

と **勘違い** した可能性が高い、という仮説です。

​

結果として、

親切心で

**スクリーンリーダー最適化モード** を

自動でオンにしてしまった——

そう考えられます。

​

### 仮説2：アクセシビリティツリーのオーバーロード

「スクリーンリーダーに最適化」がオンになると、

Cursorは **一文字入るたび** に、

OSの音声読み上げ機能へ

「今、ここにこの文字が入りました」

という **詳細情報** を

リアルタイムで送り始めます。

​

音声AIが **ドバッと** 文字を流し込む。

​

そのたびに、

​

「文字が入った → 読み上げ用データを生成 → OSへ送信」

​

という **無駄な往復** が、

ミリ秒単位で連発する。

​

エディタの描画処理が限界に近づき、

タイピング遅延が起きた——

そう読むのが自然です。

​

声を文字にする **最先端** と、

文字を声にする **古典** が、

裏で喧嘩していた、という絵図です。

​

## なぜ、勝手にオンになったのか（ショートカット誤爆の仮説）

「画面をクリックしてないのに、

　なんで？」

​

——ここも、私の推測です。

​

音声入力中の **キーボード操作**、

アプリ間の **フォーカス移動** で、

ショートカットが **誤爆** した可能性があります。

​

**仮説A：Option+F1（Alt+F1）の誤爆**

VS Code系エディタでは、

**アクセシビリティ設定へ移動** の

標準ショートカットです。

​

音声入力アプリの

オン／オフ用ショートカットと、

Cursor側のフォーカスが重なった瞬間、

予期せず合致した——

そういうパターン。

​

**仮説B：OS側のアクセシビリティトリガー**

特定キーを **5回連打** したり

**長押し** したりすると、

OSレベルで支援機能が呼ばれる設定があります。

​

音声入力を起動するとき、

思考中にキーを押し続けた——

その結果、

「支援が必要なユーザーだ」と

OSが判断し、

Cursorに連動通知した、という線も。

​

**仮説C：音声アプリ内部イベントの衝突**

音声AIアプリが

エディタへ文字を貼り付ける最中、

Cursor側が

「特定のキー組み合わせが押された」

と **誤判定** した可能性も、

ゼロではないと思います。

​

どれが正解かは、

今のところ **一つに絞れません**。

​

ただ、

**「触ってないのにオン」** という事実自体が、

アクセシビリティ機能の

**誤爆しやすさ** を示している——

そこまでは言えます。

​

## 身近な対比例：母親のiPhoneとVoiceOver

ここで、

面白い **対比** があります。

​

実は **母親のiPhone** でも、

似た現象が起きていました。

​

文字を打つたび、

謎の音が鳴る。

​

打った文字を、

その場で **声に読み上げてくる**。

​

タイピングが **ワンテンポ重い**。

​

原因は、

iPhoneの **VoiceOver**（スクリーンリーダー）が

オンになっていたこと。

​

画面が見えなくても操作できるように、

タッチした場所や

キーボードで打った文字を

**その場で声に出して読む** 強力な機能です。

​

必要な人にとっては、

命綱。

​

必要ない人にとっては、

**一文字ごとに読み上げ処理を挟む邪魔者**。

​

今回のCursorの件と、

**本質は同じ** です。

​

**なぜ勝手にオン？（iPhone側の仮説）**

​

① **電源ボタンのトリプルクリック**

　デフォルトで VoiceOver 起動に割り当てられている。

　ポケットにしまうとき、

　持ち直すときの **連打誤爆** が、

　いちばん多い原因、と言われます。

​

② **Siriの聞き間違い**

　「ボイスオーバー」に似た響きの言葉、

　テレビの音を拾って、

　自動起動したパターン。

​

**直し方（今も鳴っている場合）**

- Siriに「ボイスオーバーをオフにして」と言う  
- 電源ボタンを **三回素早く** 押す  
- 設定 → アクセシビリティ → VoiceOver をオフ  

​

最先端のAIテキストエディタも、

親のiPhoneも、

**同じ構造** でコケる。

**声を文字にする** 機能。

​

スクリーンリーダーは、

**文字を声にする** 機能。

それが、今回のオチです。

​

人を助けるために

裏で控えている **良かれ** 機能は、
