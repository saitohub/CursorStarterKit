### 4. **← 後日談セクション（新規挿入・のらみさん風：生々しい数字 + 使えるワーク）**

3週間後の振り返り。困ったことと、その後の変化を項目ごとに。

**＝ のらみさん風「生々しい数字＋使えるワーク」を盛り込む ＝**

#### 4-1. 新しいものへの拒否感→理解で解決
「新しいツール＝困る」という心理的な拒否感があった。でも使い方を理解すれば解決する。

**使えるワーク：** ツール乗り換え時は「困ったことメモ」を 3 週間つけて、何が「慣れ」で何が「本当の欠陥」かを分ける。

#### 4-2. ショートカットに慣れた
Windows ユーザーだったから Mac のショートカットに慣れてなかった。**3週間で普通になった。**

**生々しい数字：** 最初は Command キー操作が 1 回に 2 秒かかってた → 今は意識せずに動く。

#### 4-3. 音声認識が向上した
かつては Aqua Voice で誤字脱字が多かった。今は精度が上がって、整形の手間が減った。これは「技術の進化」。

**生々しい数字：** 以前は 1 分の音声 → 5〜10 分の編集時間。今は 1 分の音声 → 1〜2 分の編集時間に短縮。

#### 4-4. 「続けていいですか」→理解と成長の機会に
煩わしいと思ってたが、実は：
- セキュリティ意識が高まった
- AI に全部任せず、自分で理解しながら使う習慣がついた
- AI の仕組みが勝手に身についた

**使えるワーク：** AI が確認を求めてくる＝チェックポイント。ここで立ち止まって「なぜこの選択肢？」を考えると、AI の思考が見える。

#### 4-5. 英語の嫌悪感→学習の機会に
システムメッセージが英語で出てくるのが嫌だった。でも、その経験があったおかげで AI の仕組みを理解した。

**使えるワーク：** 英語エラーが出た＝AI が何をしようとしてるか、読む好機。辞書いらずで「AI の意図」が学べる。

#### 4-6. チャット入力不可→対処法で解決
Esc を押せば治ることを知った。最初は面倒だったが、今は慣れた。

**使えるワーク：** ツール使用時の「謎の不具合」は、先人の解決策を探す→知識になる。問題解決プロセス自体が学習。

#### 4-7. セキュリティと削除が怖い→**今も課題**
これだけは「解決した」ではなく「今も怖い」。API やパスワード設定は石橋を叩いてやってる。

**（重要ポイント：全部解決した、ではなく、現実的に「今も課題」として継続。この誠実さが信頼を作る）**

#### 4-8. 自分でアプリを作成できた→達成感・励み
音声入力アプリを自作。これが大きな励みと達成感になった。

**生々しい数字：** 1 日で 3 つの改造を完成させた＝Claude Code の「整理→実装」スピードが実感できた瞬間。

#### 4-9. Claude Code の本質：設計＋思考の学習機会
Cursor は編集に特化。Claude Code は：
- 全体の設計を示してくれる
- 目的・ゴールが明確なら、道のりを細かく示してくれる
- 「なぜそうしたのか」「どういう流れか」を振り返って分析する機会を与える
- それが「自分の考え方の勉強」になる

**使えるワーク：** AI に「なぜこうしたのか」と逆質問する。その答えを見ると、自分の思考の抜け漏れが見える。
