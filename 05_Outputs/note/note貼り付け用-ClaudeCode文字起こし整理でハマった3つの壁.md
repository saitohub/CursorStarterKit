Claude Codeで文字起こしを整理してたら、3つの壁にぶつかった話


これはエンジニアじゃない普通のビジネスマンが、Claude Codeを使い倒そうとして詰まった記録です。

「AIで作業を効率化したい」と思っている人向け。開発者向けの話じゃないです。


―――


やってたこと


購入した動画講座の文字起こしテキスト（.txt）を、Claude Codeに渡してObsidianのVaultに整理保存する作業をしていた。

19本分。

流れはシンプルで、Gmailに届いた添付ファイルのテキストをコピーして、チャットに貼り付け、「○講に保存して」と指示するだけ。

ところが途中から、毎回ストレスがかかるポイントが3つ出てきた。


―――


壁1：ファイルを書いた後、文字が入力できなくなる


Claude Codeがファイルを書き終わると、なぜか次のチャット入力ができない。

キーボードを叩いても何も起きない。

ESCを押すと直るんだけど、「256ライン」みたいな謎のテキストが残る。毎回これが出てきてうんざりしていた。

原因：ターミナルの「ページャー」という機能が起動して、キーボード入力を横取りしていた。長い出力が出ると自動でスクロール表示モードになる仕様。

修正：~/.zshrc に1行追加。

export PAGER=cat

これでページャーが起動しなくなった。Claude Codeを再起動したら完全に直った。

ちなみにESCじゃなくてqを押すのが正しい脱出方法らしい。知らなかった。


―――


壁2：長い文章を貼り付けると「256ライン」と表示されて中身が見えない


テキストを貼り付けても、全文が表示されず「256 lines」みたいな行数だけ出てくる。

「ちゃんと全部貼れてるのか？」が確認できないのが地味にストレスだった。

原因：これはClaude Code自体の仕様。長いテキストを入力欄に貼り付けると、UIが崩れないよう行数表示に切り替わる。

実は大丈夫だった点：テキスト自体はちゃんと取り込まれている。Enterを押せば全文が送信される。

ただ「途中で切れてないか確認したい」という用途には全く使えない。これはAnthropicへのフィードバック案件。


―――


壁3：Gmailからコピーすると途中で切れる


Command+Aで全選択してコピーしても、保存されるテキストが途中で終わっている。

「なんで切れるの？」としばらく謎だった。

原因：GmailはテキストファイルのインラインプレビューをするときK文字数の上限で表示を打ち切る。Command+Aで選択できるのは「表示されている部分」だけ。

解決策：添付ファイルをダウンロードして、テキストエディタで開いてからコピーする。

ただしClaudeにドラッグ&ドロップはできない（反応しない）。

なので「! cat ~/Downloads/ファイル名.txt」とターミナルに打つと、ファイルの中身をそのまま読み込める。これが一番早かった。


―――


まとめ


3つまとめると、

・入力できなくなる → export PAGER=cat を追加して再起動
・貼り付けが見えない → 仕様。Enterしたら届いてる
・テキストが途中で切れる → Gmailではなくダウンロードしてから cat コマンドで読む

AIツールは「使えば全部うまくいく」わけじゃなくて、こういう地味な詰まりポイントが必ずある。

エンジニアじゃない人ほど、ここで「自分には無理だ」と思って諦めやすい。

でも原因がわかれば全部解決できる。

ゲシュタルトを作る、というのはこういうことだと思う。「なんか動かない」じゃなくて「これはページャーの問題だ」と言えるようになること。

そうなると、次に何か詰まっても自分で調べて解決できるようになる。
