# 思考の結晶を消さないために。Obsidianの中身をGitHubに10分ごと逃がす話

> サブタイトル案：「サイジムクエスト」の装備に、無料の自動バックアップを1つ足した

---

## リード（導入）

こんにちは、サイジムです。

最近は **Obsidian・Cursor・Aqua Voice** の3つを軸に、「もう一人の自分（AI分身）」を育てる **サイジムクエスト** を続けています。日々のジャーナル、本のメモ、Cursorとの壁打ちログ。気づくと、Vaultの中身は**自分でも見直しきれない量**になってきました。

そんなある日、ふと手が止まりました。

> 「いまこのPCが壊れたら、ここまで積み上げた思考は、どうなるんだろう」

煽るつもりはなくて、ただ事実として書きます。**Obsidian は基本ローカル保存**で、PCの故障、ストレージの逼迫、誤削除——どれも誰にでも起こります。それで、僕は自分のVaultを **GitHub に 10分おきに自動で逃がす環境** を組みました。今回の note は、その全手順を **PDF 1冊** にまとめた告知です。

---

## このPDFで起きること（事実ベース）

- **10分ごとの自動バックアップ**：Obsidianを開いて作業している間、裏側で自動コミット → GitHubに送信（Obsidian Git プラグインを使う）。
- **PCを買い替えても、`git clone` 1回で取り戻せる**：新しいPCで同じVaultが、ほぼ同じ形で戻ってくる。
- **GitHubの「プライベートリポジトリ」を使う**：個人利用なら無料の範囲で運用できる。中身は**自分以外には見えない**設定で置く。

> 念のため：データを「絶対に失わない」とは言いません。**3-2-1の考え方**（コピー3つ／メディア2種類／別の場所に1つ）の中で、**「別の場所に1つ」を埋める一手**として位置づけています。

---

## なぜ「PCの外」に逃がす必要があったか

僕がいちばん怖かったのは、PCの故障そのものよりも、**「PCの容量に縛られて、置き場を考え始める」状態**でした。

容量が増えるたびに、「動画はどこに移そう」「このフォルダ消そうか」と、**創作の手前で判断疲れ**が始まる感覚。これは続けるほど効いてきます。

GitHubにミラーがあると、その判断がだいぶ軽くなりました。**PCは作業場、GitHubは倉庫**、と役割を分けた感じです。

---

## このPDFを手にしたあとの状態

このバックアップ環境を組むと、ふだんの執筆まわりがこう変わります。

- **執筆中の「いま壊れたら…」が気にならなくなる**。10分ごとに勝手にクラウド側へ反映されていく安心感。
- **PCを買い替えても、ノートを取りに帰れる**。新しいPCで `git clone` するだけ。
- **コストは基本的にゼロ**で運用できる（GitHubの個人プライベートリポジトリの範囲）。

---

## 「GitHubとかGitとか難しそう」と思っている自分へ

正直に書くと、僕も最初は同じでした。「コマンドってターミナル開くやつ？」のレベルから入りました。

だからこのPDFは、**WindowsとMacの両方**をカバーしつつ、**専門用語より「どのボタンを、どの順番で押すか」**に寄せました。詰まりやすいポイントには、画面寄りの解説と、ありがちなエラーの対処を付けてあります。

含まれているのは、ざっくりこの順番です。

1. GitHubアカウントの確認（持っていなければ作る）
2. Gitと GitHub CLI のインストール（基本コピペ）
3. VaultとGitHubのひも付け（1回だけ）
4. Obsidian Gitプラグインで「10分ごと自動同期」に切り替え
5. うまく動かないときの確認ポイントと、`git clone` での復元
