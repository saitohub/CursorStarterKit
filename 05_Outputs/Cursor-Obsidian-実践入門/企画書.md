# Cursor-Obsidian-実践入門 企画書

> 商品の設計図。全工程を通じてここに決定事項を蓄積する。

## コンセプト

### 一文コンセプト（確定：B）

行動が不安で止まりがちな人が、AIに伴走してもらいながら整理・まとめを習慣化し、学びを自分の言葉と体験に落とす入門講座。

### 補足（設計の前提）

- **ツール**: AIエディター（Cursor）と Obsidian。教材は**ノート中心**のイメージ。
- **商品形態**: **単発**の講座（プログラム）。
- **講師の立脚**: 自分が**約1ヶ月触った体験と変化**を、事実ベースで渡す（上からの権威付けはしない）。

### 変化の方向性（理想像）

- 音声入力などで「書く・記録する」が軽くなり、日記・ジャーナル・学びのまとめが**止まりにくく**なる。
- 過去の体験を、学びの教訓や例に**引きつけて自分ごと**にできる。
- 振り返りと次の行動にエネルギーを回せる（「人生が豊かになる」は理想のひとつの言い方として、後のコピーで言い換え可能）。

## ターゲット

### レベル感

- **AI・AIエディターは初心者**に近い。または一度触ったが**続いていない**人。

### 現在の状況（イメージ像）

- **30代〜40代**。仕事に追われ、**空き時間や朝**などに読書・学びをしている。
- 講座や本にお金や時間を使ってきたが、**実践や成果に結びつきにくい**。いわゆる**セミナージプシー**に近い状態を自覚している人も含む。
- キャリア上、**これ以上の昇進**をあまり感じていない、などモヤモヤがある人。

### 痛み

- 学びが**身につかない・積み上がらない・忘れる**。不安があると**動くことまで抜け落ちる**。
- 周りと比べて頑張っているのに、**お金・出世・人間関係・満足感**として形が見えにくい。

### この講座のあと、こうなっていてほしい

- 日記・ジャーナル・日々の学びを**まとめ・残し・見返す**サイクルが回り始める。
- 学びが頭に戻ってきて、**発想や次の小さな行動**（例：企画・商品を形にする一歩）につながりやすくなる。
- **自分の言葉と体験**で整理できる感覚が増える。

### 向かない人（たたき台）

- **すでに Cursor を業務で常用**しており、入門の手引きを求めていない人。
- **コード中心の開発**を主目的に、エディター習得を最短で求める人（本講座の主眼はそこではない）。
- **ノート・振り返りを一切したくない**人。
- 講師に**長年のエンジニア実績や大きな数字**を前提に期待する人（提供するのは主に**1ヶ月の実践と再現手順**）。

## 解決する問題

### 表層の困りごと

- 読書や講座で入ってきた情報が**ストックにならず**、あとから使えない。
- メモは取っても**見返さない・探せない**ので、学びが続かない。
- **不安があると手が止まる**。「何から書けばいいか分からない」で終わる。

### 本質（この講座で扱う“問題の芯”）

- **「学ぶ」と「残す」と「振り返る」と「次の一行動」**がつながっていない。
- 人間側の都合として、**忘れること自体は必要**なこともあるが、**忘れすぎて積み上がらない**状態に留まっている。
- その結果、頑張りが**自分の言葉・自分の体験**として整理されず、**満足感や再現性**として見えにくい。

### なぜ今まで解決しにくかったか（仮説）

- **摩擦が高い**: 手書き・手打ち・整える作業が重く、続かない。
- **設計がない**: フォルダもノートの型もなく、あとから検索・再利用できない。
- **伴走がない**: 止まったときに「次の一文」を一緒に考える相手がいない（AIがその役を補助できる）。

## 解決の仕組み

### 手段の組み合わせ

1. **AIエディター（Cursor）**で、文章の下書き・整形・要約・問いの生成を**軽い操作**で回す。
2. **音声入力**で、思いつきや走り書きを**速く記録**に落とす（誤字脱字の負担を下げる）。
3. **Obsidian**で、日記・ジャーナル・読書メモを**同じ場所に蓄積**し、後から**検索・見返し**できる形にする。

### なぜこれで進むか（他手段との違いの置き方）

- **ブラウザのチャットだけ**: 会話は流れやすく、**自分のVaultに資産として残りにくい**。
- **従来のメモアプリだけ**: 保存はできるが、**文章化・構造化・次の行動への翻訳**が重いままになりやすい。
- **この組み合わせ**: 「記録の軽さ（音声＋AI）」と「資産の置き場（Obsidian）」を**同じループ**に乗せる。

### 受講後の最小ループ（ゴールの動き方）

**捕捉 → 粗い記録 → AIで整える → Obsidianに格納 → 短い振り返り → 次の一歩を一行で書く**

## 商品設計

### 形式

- **単発購入**の講座（継続サブスクは前提にしない）。
- 受講者が手元で進める**ノート型教材**（Markdown中心。Obsidianで開く想定）。
- 動画は**なくても成立**させるが、あれば「短い画面収録」でセットアップと操作感だけ補助（要否は後で決定）。

### note 単品（確定）

- **チャネル**: note の**有料単品**（**1本の読み物**として提供）。
- **メインタイトル**: 頑張って学んでも、手元に残らなかったときの次の一手
- **サブコピー（説明欄先頭用）**: CursorとObsidianで、音声入力とAIに伴走してもらいながら「書く・残す・振り返る」を回し始める話（開発者向けではない）
- **補足**: メルマガ／LINE の長いファネルは**当面やらない**。無料記事で誘導するのは**任意**。

### 期間の目安

- **自己ペース**。目安として **2週間〜4週間**で一周できるボリューム（週あたりの負荷は低め）。

### 価格・枠

- **価格**: 未決定（市場・提供範囲・サポート有無で後決め）。
- **定員・サポート**: 未決定（テキストのみ／質問窓口あり 等）。

### 含まれるもの（たたき台）

- Cursor / Obsidian の**初期セットアップ手順**（つまずきポイント付き）。
- **フォルダ構成と命名**の提案（最小構成から始める）。
- **日記・ジャーナル・読書メモ**のテンプレート集。
- **AIへの依頼の型**（例：要約、言い換え、問い出し、自分の体験へ接続）。
- **週次の振り返り**の短い型。
- **よくある詰まり**（プライバシー、同期、バックアップ、使いすぎ）への注意書き。

## カリキュラム

> 章立ては教材の見出しにそのまま使える粒度。必要なら後で統合・分割する。

### 第0章　はじめに（期待値の調整）

- この講座でできること／しないこと（開発者養成ではない、など）。
- 講師の立脚：**約1ヶ月の実践**と、そこから得た**再現手順**。

### 第1章　「残す」が効く理由（短く、事実ベース）

- 学びが積み上がらないとき、何が抜けていることが多いか。
- 最小ループ（捕捉〜次の一行動）の全体図。

### 第2章　環境をつくる（Cursor + Obsidian）

- インストール、最低限の設定、日本語・音声入力の扱い（環境差がある旨の注記）。
- Vaultの作り方、**最初は浅く広くない**構成にする。

### 第3章　毎日回す：日記・ジャーナル

- テンプレを使った**3分版／10分版**。
- 「書けない日」用の逃げ道（箇条書きだけ、音声だけ、など）。

### 第4章　学びを残す：読書・インプットメモ

- 引用の扱い（著作権・引用の常識レベルの注意）。
- メモ → 自分の一言 → 行動アイデア、までをAIで補助する流れ。

### 第5章　自分ごとにする：体験の引きつけ

- 過去の出来事を、いまの学びに**例え・教訓**として接続するプロンプト例。
- 根拠のない盛りはしない（事実と解釈を分ける）。

### 第6章　振り返りと検索

- 週次レビューの型、タグ／リンクの**最小運用**。
- 「探す・繋ぐ」習慣を増やす小ワザ。

### 第7章　次の一歩（講座の出口）

- 小さなアウトプット例（ブログ1本、企画メモ1枚、業務の改善メモ1枚）。
- 続けるときの落とし穴（ツール遊び、完璧主義）への注意。

## 販売導線

### note 単品向け（現行）

```
認知（X・無料note 等／任意）
  → note 商品ページ（説明文＝ミニLP）
  → 購入（本文はそのまま閲覧）
  → 最初の15分（本文内チェックリスト）
```

### 全体の流れ（汎用・たたき台／別チャネル用）

```
集客（発信チャネル）
  → リストイン（特典）
  → 事前教育（メール中心でも可／短動画があれば併用）
  → セールス（簡易LP または 短いVSL）
  → 購入後オンボーディング（最初の1ノートまで誘導）
```

### 集客（チャネル）

- **主**: **note 単品**。
- **任意**: 無料記事・X など。メルマガ／LINE は**当面なし**でも可。

### リストイン特典（案）

- 「**最初のVault構成図**」＋「**3分ジャーナルテンプレ**」（PDFまたはMarkdown）。
- もしくは「**AIに頼む一文テンプレ10個**」。

### 事前教育（案）

- **2〜3通**のメール、または**1本の短い動画**で十分かもしれない（単発・低価格帯なら短く）。
- 伝える核: *学びが残らない構造* → *記録と振り返りの軽さ* → *CursorとObsidianの役割分担*。

### セールス（案）

- **簡易LP**（長文VSLは必須にしない）。必要なら**5〜10分の軽い説明動画**。
- 反論処理の軸: 「自分は初心者」「時間がない」→ **最小ループとテンプレ**で回す設計であること。

### 販促（案）

- **ローンチ期間**の有無、**早期特典**の有無は未決定。決まったら `promotion-config` に落とす。

### 購入後

- 教材ダウンロード or Vault配布、**最初の15分でできるチェックリスト**を同梱。
